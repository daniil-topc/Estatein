## Выполненные изменения

1. Подготовлены WebP-варианты hero шириной 480, 768, 960, 1440 и 1840 px. Для каждого фото недвижимости — 480, 864 и 1296 px. `srcset` и `sizes` соответствуют размерам карточек в CSS.
2. Hero получает `loading="eager"`, `fetchpriority="high"` и responsive preload с теми же кандидатами и размерами. Декларации preload и самого изображения совпадают.
3. Фотографии недвижимости и авторов сохраняют `loading="lazy"`; добавлен `decoding="async"`. Аватары переведены в WebP без потерь видимых пикселей.
4. Оба локальных Urbanist преобразованы в WOFF2. Сохранены все 496 глифов, 491 символ, метрики и ось веса 100–900. Предзагрузка используется для обычного начертания; `font-display: swap` сохранён.
5. Убрано подключение пустого `css/footer.css`. Когда в нём появятся стили будущего футера, его нужно подключить обратно.
6. `will-change: transform` для карточек отзывов включается в состоянии `.is-tilting`, чтобы не держать эту подсказку постоянно на трёх карточках.

Подходы соответствуют рекомендациям по [адаптивным изображениям](https://web.dev/learn/design/responsive-images?hl=en), [загрузке шрифтов](https://web.dev/learn/performance/optimize-web-fonts) и [ограниченному применению will-change](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/will-change).

## Настройки доставки и публикация

GitHub Pages уже отдаёт CSS с `Content-Encoding: gzip`. Для `css/pages/home.css` в исходной опубликованной версии измерен сжатый ответ 2584 байта. Создавать отдельные gzip-файлы для этого не требуется.

У HTML и изображений измерен `Cache-Control: max-age=600` — 10 минут. Срок кеширования задаётся слоем доставки GitHub Pages; локальная правка ассетов этот HTTP-заголовок не настраивает.

Оптимизация опубликована на GitHub Pages. После push проверены 43 ресурса страницы, включая все варианты srcset, стили, скрипты и WOFF2: все ответы HTTP 200. WebP и WOFF2 загружаются с новыми размерами файлов.

Рекомендуемое название коммита: `Оптимизирована загрузка изображений и шрифтов`.
